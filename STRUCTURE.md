# UniGrid Architecture & Directory Structure

This document details the architectural blueprint, folder organization, and file responsibilities of the **UniGrid** codebase. It serves as a guide for developers to easily navigate, maintain, and expand the platform.

---

## 🏗️ Architectural Overview

UniGrid is built on a modular, clean-architecture framework using the following core paradigms:
* **Frontend Framework:** Flutter & Dart (Cross-platform support for Android, iOS, and Web).
* **State Management:** `Provider` pattern for reactive state propagation and dependency injection (User context, Theme configurations, Network connection states).
* **Primary Database & Sync:** Cloud Firestore for real-time document syncing, chats, class test marks, schedules, and bulletins.
* **Storage Provider:** Supabase Storage (accessed via direct REST/SDK bindings) optimized for handling large note PDFs, slides, and chat media files.
* **Push Services:** FCM (Firebase Cloud Messaging) and OneSignal configurations for real-time announcements and chat notifications.

## 📄 Core Codebase File Index

Below is a detailed breakdown of the purpose and responsibility of every file inside the `lib/` directory:

### 📍 Root Application Files

* **[`lib/main.dart`](file:///b:/UniGrid/lib/main.dart)**
  * **Role:** Entry point of the entire application.
  * **Responsibilities:**
    * Initializes Firebase services natively based on platform metadata.
    * Sets up structural dependency providers (`AppUser?`, `ThemeService`, `ConnectivityService`).
    * Wraps the root MaterialApp in a series of global middlewares (`NetworkAwareWrapper`, `VersionAwareWrapper`) to keep the app responsive to network changes and OTA update requirements.

* **[`lib/firebase_options.dart`](file:///b:/UniGrid/lib/firebase_options.dart)**
  * **Role:** Platform-aware Firebase metadata configurations.
  * **Responsibilities:** Autogenerated configuration map detailing Firebase project keys and credentials for Android, iOS, and Web.

### 📦 1. Models (`lib/models/`)

Contains the structured Dart class declarations mapping Firestore and Supabase document records into typed objects.

* **[`lib/models/models.dart`](file:///b:/UniGrid/lib/models/models.dart)**
  * **Role:** Centralized data schema registry.
  * **Responsibilities:**
    * **`AppUser`**: Represents student profiles, emails, departments, sections, and authorization scopes (`isCR`, `isMaster`, `isApproved`).
    * **`NotesModel`**: Maps uploaded notes, files, URLs, uploader emails, and submission timestamps.
    * **`CourseModel`**: Maps course registry items including titles, codes, syllabus links, and list of Class Test marks.
    * **`RoutineModel`**: Defines time slots, weekday markers, subject names, rooms, and instructor profiles.
    * **`AnnouncementModel`**: Standardizes classroom broadcast cards (text, files, dates, and dynamic categories).
    * **`ChatMessage`**: Standardizes chat text, image attachments, sender identifiers, and timestamp mappings.

## 🛠️ Best Practices for Code Navigation

1. **Adding a New Feature/Screen:** Create the page layout inside `lib/screens/`, hook up any specific elements as shared widgets in `lib/widgets/`, configure models in `lib/models/`, and route it within `lib/screens/main_screen.dart`.
2. **Handling Backend Operations:** Never call Firestore or Supabase directories directly inside screens. Use or write clean wrappers in `lib/services/` and use them asynchronously.
3. **Applying Styles:** Do not declare arbitrary/ad-hoc colors or typography inside components. Always reference the pre-configured design palette inside `lib/utils/constants.dart` to maintain the app's premium HSL glassmorphic design language.
